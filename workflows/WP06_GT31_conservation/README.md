# GT31 reference-core conservation and mapping onto viral F2Y1U4

This is the reproducible code package for the Q18515–F2Y1U4 core-coloring
analysis in Supplementary Figure X-2-2. It implements the essential analysis
steps from the archived C012 GT31 workflow: select representatives, define a
reference-only structural core, and map that core onto F2Y1U4.

The core numerical modules are preserved unchanged from the archived analysis.
A portable driver was added on 22 October 2026. This directory contains the
code, parameters, instructions, 18 input PDBs, archived Foldseek scores,
FoldMason alignments, expected outputs, and validation record. Download or
clone the complete repository to obtain both code and data together.

After installing Python dependencies, the rerun needs no GPU, network access,
Foldseek executable, or FoldMason executable.

## Run

Download the repository using GitHub's **Code → Download ZIP** option and
extract it, or clone it with Git. All required scientific input files are
included under this workflow directory.

From the repository root, with Python 3.12:

```bash
python -m pip install -r workflows/WP06_GT31_conservation/requirements.txt
python workflows/WP06_GT31_conservation/scripts/run_analysis.py
```

The script also works when invoked by its full path from another working
directory. Outputs are written to `workflows/WP06_GT31_conservation/output/`.
To use a different new or empty directory:

```bash
python workflows/WP06_GT31_conservation/scripts/run_analysis.py --outdir gt31_run
```

The driver checks package checksums before running and stops if reference
selection, any core assignment, local metrics, or F2Y1U4 mappings disagree with
the archived outputs. A successful run ends with `"status": "PASS"` and writes
`validation.json`. Expected runtime is recorded in the included validation
record; this is a CPU postprocessing workflow.

## What is reproduced

| Essential step | Code | Result |
|---|---|---|
| Select representatives (previous step 3) | `src/vgt_constraints/medoids.py` | Q9N294, A0A3B3R5I0, Q18515, Q1RLK6 |
| Define reference pan-core (previous step 5) | `pan_core.py`, using `aggregate_local_lddt()` from `constraints.py` | 98 strict columns; 147 supported columns including strict |
| Map core to F2Y1U4 (previous step 6) | `map_query_to_pan_core()` in `pan_core.py` | 93 strict and 41 supported-only query residues |
| Write classes and PyMOL view (previous step 7) | `scripts/make_query_core_classes.py`, `scripts/make_pymol_pml.py` | Class-annotated PDBs and a self-contained PML |

`scripts/run_analysis.py` coordinates these steps. The separate exploratory
residue-analysis workflow is not executed. `constraints.py` remains intact
because it supplies the original local geometry calculation used by the core
caller. `common.py` supplies structure parsing, alignment mapping, configuration,
and PDB output functions.

## Reproduce the three summary bars

The companion [query-comparison workflow](QUERY_COMPARISON.md) reproduces
sequence identity **16.42%**, query coverage **99.25%**, and alignment TM-score
**0.7996** as the unweighted mean of four subcluster medians. Run from the
repository root (Python standard library only; no dependency installation needed):

```bash
python workflows/WP06_GT31_conservation/scripts/summarize_query_comparisons.py
```

It writes per-reference comparisons, subcluster medians, `bar_summary.tsv`, and
a validation record under `query_comparison_output/`. All inputs are included.
This calculation uses the full archived alignments/comparisons and does not
restrict the scores to the strict or supported core residues.

## Reference set and alignment

The 17 references belong to four annotation-defined groups: SC01 B3GALT5-like
(5 proteins), SC02 generic B3GALT-like (4), SC03 C1GALT1 (4), and SC04 B3GNT3/4
(4). Membership is supplied in `inputs/reference_members.tsv`; the workflow
does not discover these groups by clustering.

The reference-only alignment is generated by **selecting 17 rows from the
archived 19-reference FoldMason alignment while retaining all 966 columns**.
This is not a new alignment of only 17 proteins. The query-inclusive alignment
contains those 19 references plus F2Y1U4. Q9N294 residue indices connect the two
alignment coordinate systems. F2Y1U4 does not influence reference core selection.

## Expected results

| Quantity | Expected |
|---|---:|
| Reference proteins / groups | 17 / 4 |
| Directional Foldseek rows, including self | 289 |
| Reference alignment columns | 966 |
| Strict reference core | 98 |
| Supported reference core, including strict | 147 |
| Supported-only reference positions | 49 |
| Strict reference positions mapped to F2Y1U4 | 93 / 98 (94.9%) |
| Supported-only positions mapped to F2Y1U4 | 41 / 49 |
| Q18515 strict / supported-only / other residues | 98 / 49 / 242 |
| F2Y1U4 strict / supported-only / other residues | 93 / 41 / 97 |

The 94.9% value is positional mapping coverage. It is not amino-acid identity
or the fraction of query residues independently passing the reference strict
criteria. Query structural similarity is separately reported in the mapping
and summary tables. This sampled reference core is not established as a
universal core of all GT31 proteins, and does not assign C1GALT1 activity to
F2Y1U4.

## Open the coloring in PyMOL

After running the analysis, use **File → Run Script** to open
`output/view_pan_core_comparison.pml` (or the file in your chosen output folder).
Both PDBs are embedded in that PML, so it does not need to locate external
structure files and does not depend on PyMOL's current directory.

Dark teal = strict, light blue = supported-only, grey = other positions.
The annotated PDB B-factor field stores `100`, `60`, or `0`; these are class
labels and must not be interpreted as pLDDT. Original confidence values remain
in `inputs/structures/`.

This view restores the core colors. It does not recreate the original figure's
structural superposition, left/right arrangement, or camera orientation.
PyMOL rendering is not part of the automated numerical validation.
