# Repository publication and push policy

- Publication-essential code, inputs, outputs, figures, results and reproducibility documentation belong in `LanNa1229/viral-gt-research-record`, which must remain PUBLIC. Obtain the user's explicit approval before publishing them.
- Exploratory/intermediate analyses, parameter investigations, validation experiments and computational records belong in `LanNa1229/viral-gt-internal-analyses`. Verify PRIVATE visibility before uploading anything.
- Never automatically publish a newly completed analysis to the public repository.
- Before every future GitHub push, obtain explicit user approval for that scoped push. An ordinary request to perform an analysis does not authorize a push. An explicit request to perform a specified migration/push authorizes only that request's named scope.
- Preserve Methods, provenance, executable code/configuration, input/output manifests, checksums, execution evidence and validation results for every analysis.
- Preserve unrelated files and user changes. Do not make additional migration/deletion decisions based on a filename or an exploratory label alone; report review candidates first.
- Do not force-push, rewrite history, delete repositories, change the public repository's visibility, or perform destructive cleanup without separate explicit user approval.

The current explicitly requested repository migration authorizes its scoped private upload and public normal-deletion/policy commit. It does not authorize later scientific-analysis uploads or history cleanup.
